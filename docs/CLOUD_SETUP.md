# 微信云开发部署说明

## 2026-11-12 车费 AA 结算与收款码

发布行程不再填写金额，发布页不显示“车费”标签或“结束后按乘车人数 AA”文案；首页、列表和编辑页也不再显示“车费结束后 AA”。首次发布前，用户必须在“我的”页面上传收款码；行程结束后由发布人填写最终车费，云端按实际乘车人数平分并生成结算单。

- 收款码保存在私有云存储 `payment-codes/`，文件 ID 仅保存在 `users.paymentCode`；不进入公开用户资料，也不由客户端直接读取。
- `profile` 负责收款码上传准备、提交、删除和本人临时地址；图片限制 2MB，校验 JPG/PNG/WebP 文件签名和内容安全。
- `rides` 负责发布门槛、`settling` 待结算状态、结算单、同行人标记转账、发布人确认收款和完成结算。
- 只有结算参与者和发布者能在 `rides.getGroup` 中拿到收款码临时地址；首页、列表、消息页和公开资料都不返回。
- 行程进入 `settling` 后保留成员和群聊；发布人确认所有同行人收款后进入 `settled`，再清理临时群。
- 小程序不代收代付，也不调用 `wx.requestPayment`；同行人通过微信转账给发布人，小程序只做金额计算和状态记录。
- 发布/编辑时云端强制使用当前用户的姓名作为发布人称呼；出校行程的出发地、返校行程的目的地强制使用当前学校名称，客户端输入框只用于展示。
- 发布页默认使用当前手机日期和时间；云端不再限制出发时间必须晚于当前时间。行程按日期有效：出发日当天一直有效，到中国标准时间次日 00:00 自动过期。
- 需要重新部署 `profile` 与 `rides` 云函数；不需要新增集合或索引。云存储权限应保持私有，不能公开 `payment-codes/`。
- `project.config.json` 的 `packOptions.ignore` 将 `cloudfunctions` 排除出小程序代码包；这只影响小程序打包，不影响通过 `cloudfunctionRoot` 部署云函数。

## 2026-11-12 网约车行程链接

拼车团页面支持发布人粘贴滴滴/高德“分享行程”链接，供已加入的同行人复制查看。链接保存在 `rides` 文档的 `externalTrip` 字段中，不新增集合，也不改变现有“小程序端不可直接读写业务集合”的权限设置。

- 只有行程发布者可以保存、更新或删除链接；只有发布者和当前拼车团成员能在 `rides.getGroup` 响应中拿到链接。
- 首页、拼车列表、`listMyGroups` 和公开行程卡片不返回 `externalTrip`。
- 云端只接受 `https://` 的滴滴/高德官方域名，拒绝自定义端口、账号信息和仿冒域名。
- 行程结束、取消、解散或过期时会将 `externalTrip` 置空。
- 需要重新部署 `rides` 云函数后生效，无需新建集合或索引。

## 2026-11-11 实时消息推送配置

聊天与消息页优先使用微信云数据库的实时推送 `watch()`，长轮询只作为降级。实时通道依赖一个只读的安全投影集合 `chat_events`，不能直接开放 `messages` 或 `conversations`：

1. 在云开发控制台手工创建集合 `chat_events`，不要依赖自动创建。新集合的默认权限可能是公开读，必须先完成下一步安全规则，再开始聊天测试。
2. 在云开发控制台打开 `chat_events` 的权限设置，选择“自定义安全规则”，粘贴：

```json
{
  "read": "auth.openid == doc.ownerOpenid",
  "write": false
}
```

3. 按 `database/indexes.json` 为 `chat_events` 建立 `owner_created` 与 `owner_conversation_created` 索引。
4. 安全规则只允许用户读取 `ownerOpenid` 等于自己 openid 的事件，客户端监听时也必须带 `ownerOpenid` 条件。事件只保存会话 ID、消息 ID、发送者公开用户 ID、昵称、文本和时间，不包含其他用户的 OPENID、手机号或完整会话成员列表。
5. 规则未配置或 `watch()` 被拒绝时，客户端会自动退回约 0.1–0.3 秒的长轮询；聊天不会不可用，但云端数据库读次数会明显增加。

双人搭子解除时，`social` 会删除对应私聊会话、消息、已读记录和实时事件；行程结束、取消、解散、过期或成员退出时，`rides` 会清理对应的 `chat_events`。这些清理失败不会阻断主操作，但会在云函数日志中记录警告。

## 2026-11-10 部署更新

本轮代码新增了全国学校选择与行程隔离、行程生命周期、临时群自动清理、双入口搭子申请、双向删除搭子、群聊、未读、订阅提醒、分页、头像安全、私有资料和定时过期清理。线上生效前必须完成以下工作：

1. 新增 `conversation_reads`、`subscriptions` 集合；连同原有集合全部设置为“小程序端不可直接读写”。
2. 根据 `docs/DATABASE_INDEXES.md` 先预览索引计划，检查重复数据后再执行 `scripts/init-database-indexes.ps1 -EnvId your-env-id -Apply`。
3. 订阅提醒现在只用于“有人加入我的拼车团”：`chat` 只负责记录用户授权额度，`rides` 在成员加入成功后向发布者发送一次通知。模板 ID 不再写入默认配置；请在 `utils/config.js` 填入，并在 `chat`、`rides` 云函数环境变量设置 `CHAT_SUBSCRIBE_TEMPLATE_ID`，留空则关闭提醒。字段仍为发送人 `thing1`、通知内容 `thing2`、拼车团名称 `thing14`、时间 `time3`。
4. `rides` 已声明 `subscribeMessage.send` 云调用权限；请重新部署 `chat` 与 `rides`，并按运行版本在 `rides` 云函数环境变量设置 `MINIPROGRAM_STATE`（`developer` / `trial` / `formal`）。聊天消息本身不再发送订阅通知。

集合完整清单：`users`、`rides`、`ride_members`、`buddy_requests`、`buddies`、`conversations`、`messages`、`chat_events`、`conversation_reads`、`subscriptions`。

`rides/config.json` 声明每 10 分钟执行一次自动过期清理；列表与群详情读取时也会惰性清理。聊天优先使用 `chat_events` 的 `watch()` 实时推送，失败时退回长轮询；页面隐藏或卸载后立即停止监听。离线提醒使用微信订阅消息，不是 WebSocket 服务。

拼车群是行程级临时群。行程结束、取消、解散或自动过期后，`rides` 云函数会清理对应的 `ride_members`、群 `conversations`、群 `messages`、`conversation_reads` 和该行程的 `buddy_requests`。已经由双方同意建立的 `buddies` 关系不会随行程删除，只会在任一方主动删除搭子时双向解除。

用户首次进入必须选择学校；学校使用教育部学校标识码保存。学号改为选填的 4-20 位字母、数字、下划线或短横线，仅本人可见，不再作为发布、入团、搭子或聊天门槛。

首次选校不消耗换校次数。已有学校后，每个自然月最多更换一次，按中国标准时间计算；限制由 `profile` 云函数事务校验，客户端提示只用于提前说明，不能替代云端校验。更新该规则后需重新部署 `profile` 云函数。

如果线上曾创建旧的 `verification_requests` 集合，本版不再读取或写入它。是否删除该历史集合应在备份并确认无业务数据后由管理员手工决定，本次代码更新不会自动删除云端数据。

头像上传现在由云函数签发随机路径，并校验 2MB 上限、JPG/PNG/WebP 文件签名、图片内容安全，成功替换后清理旧头像。所有业务数据均使用云端；云端发布失败时直接报错，不会生成本地订单。

本轮尚未重新部署或修改线上数据库。具体当前状态以 `docs/PROGRESS.md` 为准。

## 环境信息

- 仓库不包含作者的小程序 AppID 或云环境 ID。
- 导入项目后，请在 `project.config.json` 和 `utils/cloud.js` 中使用自己的配置。
- 云函数目录：`cloudfunctions/`

AppID 与环境 ID 不是密钥，但公开仓库使用占位符，避免 Fork 后误连作者环境。AppSecret、支付密钥、私钥和访问令牌不得写入代码或提交。

## 首次部署步骤

1. 在微信开发者工具中重新编译项目，确认左侧出现“云函数”目录标识。
2. 在云开发控制台创建上方列出的全部集合。
3. 把这些集合的权限设置为仅云函数/管理端可读写，不开放小程序端直接写入。
4. 依次右键 `cloudfunctions/login`、`profile`、`social`、`chat`、`rides`。
5. 对每个目录选择“上传并部署：云端安装依赖”。
6. 等待五个云函数均显示部署成功，再重新点击“编译”。
7. 进入“我的”页面，状态应从“云函数待部署”变为“微信身份已连接”。
8. 填写并保存资料，`users` 集合中应出现当前用户记录。

## 本轮更新后的重新部署

学校范围和资料规则修改涉及五个云函数，需要依次右键以下目录并选择“上传并部署：云端安装依赖”：

1. `cloudfunctions/login`
2. `cloudfunctions/profile`
3. `cloudfunctions/social`
4. `cloudfunctions/chat`
5. `cloudfunctions/rides`

五个函数部署完成后重新编译小程序。旧用户首次进入会先选择学校；没有 `schoolId` 的历史行程不会进入任何学校的新列表，需要管理员按实际情况补充学校标识或保留为历史数据。

不要把云函数的 `node_modules` 上传到 Git；依赖由云端根据各函数的 `package.json` 安装。

## 数据集合

首次部署前需要在控制台创建以下集合，之后云函数会写入数据：

| 集合 | 用途 |
| --- | --- |
| `users` | 微信身份关联的个人资料、当前学校、私有收款码文件 ID；学号和收款码仅本人及授权结算成员可见 |
| `buddy_requests` | 搭子申请及处理状态 |
| `buddies` | 双向应用内搭子关系与备注 |
| `conversations` | 私聊会话及成员列表 |
| `messages` | 聊天消息 |
| `rides` | 云端行程与拼车团基础信息 |
| `ride_members` | 拼车团成员、角色和加入时间 |

## 权限建议

当前所有敏感写操作都通过云函数校验 OPENID。除 `chat_events` 按上面的自定义规则只开放本人只读外，其余数据库集合应设置为“不允许小程序端直接读写”或等价的仅云函数/管理端访问模式，避免客户端绕过权限校验伪造好友、成员或消息。

云存储中的 `avatars/` 用于用户头像。正式发布前还应补充举报、拉黑、账号注销和数据删除流程。

## 当前云函数能力

- `login`：从可信微信上下文读取 OPENID，创建或更新用户，并生成不暴露 OPENID 的 `CP-` 搭子码。
- `profile`：读取和保存当前用户资料与当前学校，限制字段与长度；学号只返回给本人；管理私有收款码的上传、替换和删除。
- `social`：通过搭子码或同一拼车群成员列表发送申请，接受或拒绝申请，列出搭子、保存备注并双向删除搭子关系。
- `social` 的群内申请会额外校验申请人与目标用户仍同属一个有效的活动拼车团；两个申请入口都必须经对方同意。
- `chat`：仅允许当前仍为搭子的用户访问双人会话；仅允许活动行程成员访问临时群聊。
- `rides`：按当前学校发布/列出云端行程，加入拼车团，列出当前学校的拼车团；校验发布前收款码，生成待结算单、记录同行人转账与发布人确认，并在结算完成后删除临时群数据。

客户端不会获得其他用户的 OPENID。搭子与聊天页面只调用 `utils/cloud.js` 的 `social`、`chat` 接口；云端不可用时显示错误或空状态，不会读取或写入本地模拟业务数据。

## 双账号验收

1. 使用账号 A 进入“我的”，保存姓名并复制搭子码。
2. 使用账号 B 进入“消息”，输入账号 A 的搭子码并发送申请。
3. 账号 A 在“消息”中接受申请。
4. 双方点击搭子进入在线会话，互发消息；另一方重新进入、下拉或点击刷新后应看到新消息。
5. 修改联系人备注后重新进入“消息”，确认备注仍从云端恢复。
6. 账号 A 发布云端行程，账号 B 加入拼车团并从成员列表向 A 发送搭子申请。

开发者工具模拟器通常只代表一个微信身份。完整验证需要两位体验成员、两台手机或两个不同的微信账号。
