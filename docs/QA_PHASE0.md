# 阶段 0 验收清单

日期：2026-11-12

## 1. 云开发配置

- [x] 在云开发控制台创建集合 `chat_events`。
- [x] 给 `chat_events` 设置自定义安全规则：

```json
{
  "read": "auth.openid == doc.ownerOpenid",
  "write": false
}
```

- [x] 按 `database/indexes.json` 创建：
  - `chat_events.owner_created`
  - `chat_events.owner_conversation_created`
- [x] 确认 `rides`、`profile` 云函数均为最新部署版本。
- [ ] 进入聊天页，确认提示为“消息实时推送中”，而不是降级提示。

## 2. 双账号主链路

账号 A：发布人；账号 B：同行人。

- [ ] A 在“我的”填写姓名、手机号并上传收款码。
- [ ] A 发布行程：出校/返校学校端自动填写，称呼自动为 A 的姓名。
- [ ] B 加入同一拼车团。
- [ ] A、B 进入群聊，互发消息；消息应在约 0.1-0.3 秒内出现。
- [ ] 关闭 B 的网络再恢复，确认聊天能继续，不出现重复消息。
- [ ] A 结束行程，填写最终车费，勾选 A、B 为实际乘车人。
- [ ] B 看到自己的应付金额、A 的收款码；点击“我已转账”。
- [ ] A 看到 B 的状态变为“已转账，待确认”；点击“确认收款”。
- [ ] B 看到“发布人已确认收款”。
- [ ] A 点击“完成结算”，确认拼车团关闭。
- [ ] 非成员账号打开该行程，确认看不到收款码和金额。

## 3. 结算并发

需要 1 个发布人 + 至少 2 个同行人。

- [ ] 发布人生成 3 人结算单。
- [ ] 两个同行人几乎同时点击“我已转账”。
- [ ] 发布人连续快速确认两人。
- [ ] 刷新结算页，确认两人的状态都保留为“已确认”，没有被覆盖。
- [ ] 再次点击同一人的确认按钮，不应改变金额或重复生成记录。

## 4. 我的拼车团分页

- [ ] 用同一账号创建或加入超过 10 个已结束/已过期拼车团。
- [ ] 再保留至少 2 个进行中或待结算团。
- [ ] 进入消息页，确认“我的拼车团”能正常显示，不出现空白页。
- [ ] 点击加载更多，确认没有漏掉待结算团。

## 5. 代码质量

- [ ] 代码依赖分析点“刷新”，无依赖代码文件数应为 0。
- [ ] 代码质量点“重新扫描”，确认：
  - 启用组件按需注入：通过
  - 不应存在无依赖文件：通过
- [ ] 预览包体应在 460 KB 左右，不应包含 `cloudfunctions`、`tests`、`scripts`、`docs`。
