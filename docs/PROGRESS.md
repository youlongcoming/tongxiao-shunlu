## 2026-11-12 修复撤销结算后无法重新生成

- 原因：撤销结算后 `settlement` 被写成 `null`，再次生成时 `settlement: record` 被云数据库当作嵌套对象合并，报 `Cannot create field 'createdAt' in element {settlement: null}`。
- 修复：所有结算对象写入改用 `db.command.set(...)` 整体替换；结算单内的 `createdAt` 改用普通 `Date`，不再嵌套 `db.serverDate()` 命令。
- 已重新部署 `rides`（14.1 KB），线上返回部署成功。
- [ ] 真机验证：生成结算 → 撤销 → 重新生成 → 修改金额 → 确认收款 → 完成结算。

- 行程、拼车团、搭子关系和聊天均只使用云端接口；云函数不可用时不生成本地业务数据。

- 云端聊天与消息页优先使用 `chat_events` 的数据库 `watch()` 实时推送，长轮询与 1.5 秒/3 秒轮询作为降级；事件按本人 openid 隔离，空闲时不产生数据库查询。
- 个人资料缓存键为 `userProfile`，头像优先通过 `wx.saveFile` 保存在小程序本地文件中。
- 旧版模拟业务缓存会在应用启动时删除，不再参与任何页面数据源。
