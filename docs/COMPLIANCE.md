# 合规说明

> 本文不是法律意见，也不构成“如何通过审核”的承诺。校园拼车涉及微信平台规则、备案、道路运输、个人信息保护和学校安全治理，具体路径应以学校法务/合规部门和当地主管部门意见为准。

## 1. 微信小程序类目与主体

微信小程序平台对“拼车/网约车/交通出行”类服务有主体和资质要求。个人主体通常不能选择拼车类目，也不能提供车辆、派单、承运或交易服务。

本项目在开发过程中遇到过明确的审核结论：

> 小程序涉及提供拼车业务，拼车属于个人主体小程序未开放类目，建议申请企业主体小程序。

因此：

- **不要**把“信息共享”当成规避类目审核的万能话术。审核员会看实际页面、功能和数据流。
- 如果产品保留行程、拼车团、AA 结算、收款码等能力，通常需要学校/校属单位或企业主体，并按平台要求提交备案与资质。
- 如果坚持个人主体，只能把产品真正收敛为信息发布/交流工具，移除拼车运输、计价、代收代付等能力，并重新评估类目。
- 小程序名称、介绍、版本描述、隐私指引和实际页面必须一致；虚假描述可能导致更严重的处罚。

## 2. 运输与校园安全

平台的产品边界应当是“信息发布与组队”，而不是“承运”：

- 不提供车辆、驾驶员、派单、调度、计价、保险或运输服务。
- 不按车费抽成，不代收代付，不承诺安全保障。
- 不鼓励疲劳驾驶、超员、非法营运或现金交易。
- 学校应保留审核、下架、暂停和要求整改的权利。

上线前应与学校保卫、学工、信息中心确认：

- 是否允许在本校开展试点；
- 是否需要校方备案/审批；
- 突发事件、交通事故、纠纷的应急联系人；
- 校内宣传、地推和数据使用的边界。

## 3. 个人信息保护

本项目会处理手机号、学校、选填学号、头像、昵称、发布内容、聊天、收款码等个人信息。上线前至少完成：

1. **数据映射**：每类信息从哪个页面/云函数收集、存在哪个集合/存储、谁能访问、保存多久。
2. **最小化**：非必要不收集；学号保持选填；收款码只在结算场景展示。
3. **告知同意**：小程序内提供《隐私政策》，说明处理目的、方式、范围、保存期限、第三方（微信云开发）和用户权利。
4. **权限边界**：手机号只向有效搭子/活动拼车团成员返回；学号仅本人；收款码仅结算参与者。
5. **删除与注销**：提供账号注销、资料删除、撤回授权的入口；无法立即删除时说明流程和时限。
6. **未成年人**：如果用户可能未满 18 岁，按学校要求和适用法律处理监护人同意与保护。
7. **第三方**：微信云开发、订阅消息、内容安全接口等需要在隐私政策中披露。

微信公众平台的“用户隐私保护指引”必须与实际代码使用的接口一致。代码使用 `wx.getClipboardData`、相册选择等能力时，不能把对应项留空或谎报“未采集”。

## 4. 内容与社区治理

上线前必须补齐：

- 文字内容审核（`msgSecCheck`）与图片审核；
- 举报入口、拉黑、屏蔽、删除；
- 管理员后台与操作日志；
- 聊天/申请频率限制与风控；
- 敏感词、广告、诈骗、非法营运信息的处置流程；
- 应急下架和用户通知机制。

## 5. 安全基线

- 数据库集合默认不对小程序端开放读写；`chat_events` 只允许本人只读。
- 云存储 `payment-codes/` 必须私有，不能公开。
- 不提交 AppSecret、支付密钥、私钥、访问令牌、真实手机号或学号。
- 云函数只信任 `cloud.getWXContext()`；不信任客户端传入的 OPENID。
- 上线前替换为自己的小程序 AppID/云环境，重新配置安全规则和索引。

## 6. 开源与责任

本仓库以 MIT 许可证开源，目的是技术学习、校园试点和产品讨论。Fork 或部署者需要自行：

- 确认所在学校/地区的平台规则、备案和运输合规；
- 完成隐私政策、账号注销、内容审核和举报后台；
- 承担运营、安全、数据和法律责任。

如果你在审核或合规上遇到具体问题，建议先咨询学校法务/合规部门和微信平台官方客服，而不是依赖仓库中的文案或代码。
